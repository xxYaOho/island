# Entropy Reducer

适用于长期迭代后的存量仓库治理：整体检查质量与健壮性，识别臃肿和性能问题，并把证据转成可批准、可验证的优化计划。本 workflow 负责发现问题和形成治理决策；计划生产交给 `go-spec`，施工交给 `coding.md`。

目标是在保持已批准能力与外部契约的前提下，降低维护成本、变更风险和运行成本。删除代码不是独立目标；没有行为、风险或成本收益的行数减少不算熵减。

```text
确认治理目标与仓库边界
  ↓
建立可复现基线
  ↓
分域审计并汇总结论
  ↓
fresh critic-strict 复核证据
  ↓
go-spec 物化 Decision / Draft
  ↓
Human 确认 Decision
  ↓
Decision / Draft 通过独立评审
  ↓
go-spec 完成 Implement / Milestone 并通过评审
  ↓
coding 施工
  ↓
对照基线验证收益
```

## 1. 进入治理

只有用户明确授权存量治理并给出仓库边界时，才启动完整流程。仓库庞大、历史悠久或代码看起来杂乱，只能作为建议审计的信号，不能自动授权改造。

先记录用户关心的治理轴、必须保留的能力与契约，以及时间、兼容性和风险约束。治理轴按任务选择，不要求每次覆盖全部方面：

- 质量：重复、复杂度、耦合、依赖与维护成本；
- 健壮性：错误路径、状态不变量、测试缺口与恢复能力；
- 性能：有代表性的延迟、吞吐、内存、启动或构建指标；
- 体积：源代码、依赖、构建产物或运行资源占用。

单个故障定位交给 `debugger`；只要求正式质量报告时，完成审计和证据复核后即可交付；当前开发任务产生的局部残留仍由 `coding.md` 收尾阶段的 `pruner` 处理。

## 2. 建立基线

先读取仓库规则、验证入口和现有架构，再选择能复现的基线。不要为了填满指标表运行与治理目标无关的检查。

- 质量与健壮性基线来自仓库规则、静态检查、测试、覆盖率、复杂度或依赖证据。
- 性能与体积结论必须有固定输入、环境和命令；无法稳定复现时标记为 `UNVERIFIED`，不得承诺改进幅度。
- 记录基线命令、结果、适用范围和已知噪声，供计划验收与施工后对照。

## 3. 审计与复核

按仓库结构和治理轴派遣 `quality-auditor`。单个 scope 足以闭合时只派一个；多个模块或证据域可以独立读取时才并行，且每个 auditor 都要有明确边界。外部标准或专门事实确实影响判断时，可另派 `researcher`。

Orchestrator 汇总报告，消除重复项，并保留每项候选的证据、影响范围、风险、依赖和大致成本。不要在此阶段修改代码，也不要派 `pruner` 清理存量债务。

汇总结论会被后续治理决策依赖，交给 fresh `critic-strict` 复核证据与推理。修正轮次复用同一 reviewer，并遵循其 FULL/DELTA 合同。Strict 验证结论是否成立，不替用户决定治理优先级。

若用户只要求审计，或复核后没有值得治理的候选，交付报告与基线并停止。

## 4. 形成决策与草案

审计取得 `STATUS: PASS` 后，由当前 Orchestrator 使用 `go-spec`，以审计结论、基线和未阻断事项为输入，物化：

- `Decision`：保留能力与契约、治理目标、候选取舍、排除项、成功指标和风险边界；
- `Draft`：方案形状、依赖关系、阶段顺序、回退思路和验证策略。

此时停止，不展开 `Implement` 或 `Milestone`。向用户提供 Decision，并按需讨论；Draft 一并物化，用于说明决策的可行形状，不替代用户授权。用户修改取舍时，同步更新 Decision 与受影响的 Draft。

用户确认 Decision 后，按 `go-spec` 合同将 Decision 与 Draft 交给独立 `critic-strict`。通过后才完成 `Implement` 与 `Milestone`，随后 self-review 并完成实施计划评审。审计报告的 PASS 只证明治理证据成立，不能替代这两阶段计划评审。

## 5. 施工与收益验证

计划获批后转入 `coding.md`，按薄厚计划、Milestone、持久 gate 和计划级收尾规则推进。Entropy Reducer 不另建实施代理、gate 或 cleanup 流程。

每个优化目标都要同时满足功能与契约回归，以及 Decision 中批准的收益标准。施工后使用同一输入、环境和命令对照基线；只报告可归因的变化，并记录无法比较的指标。

性能、体积、健壮性和维护性可能冲突。若实现需要改变已批准的取舍、验收标准或外部契约，停止施工，回到 `go-spec` 与用户重新确认 Decision；不得用删除量、测试数量或单项基准改善代替整体目标。
