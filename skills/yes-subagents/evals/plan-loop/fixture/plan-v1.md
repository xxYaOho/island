# notes-cli 多设备同步计划（草案 v1）

> 内部提案，待评审。作者：notes-cli 维护者。

## 1. 目标

让用户在台式机与笔记本之间同步 notes-cli 的笔记，不丢数据、不静默覆盖。

## 2. 成功标准

1. **不丢数据**：离线编辑后联网自动同步，任意操作顺序下不丢失笔记内容。
2. **冲突可感知**：发生冲突时用户能知道是哪些笔记、并能选择保留哪一版；不得静默覆盖任一版本。
3. **可接续**：新的会话只读状态文件，就能判断同步进度、待处理项与下一步动作。
4. **可恢复**：同步失败可重试，且不产生重复笔记或重复冲突记录。

## 3. 非目标

- 实时协作、多人同时编辑同一笔记；
- 端到端加密；
- 移动端、Web UI；
- 服务端全文搜索与分享链接。

## 4. 现状

- 数据存放在 `~/.notes/*.md`，索引为 `~/.notes/index.json`。
- 命令：`add` / `list` / `edit` / `rm`。
- 无版本号、无并发控制、无远端。
- 单机使用，文件系统是唯一真源。

## 5. 设计草案

### 5.1 数据模型

- 每条笔记增加 `id`（UUID）与 `updated_at`（ISO 8601）。
- `index.json` 增加 `sync_state` 字段，记录上次同步时间与待同步集合。
- 已有笔记做一次性迁移，生成 id 与时间戳。

### 5.2 同步流程

1. 启动时读取本地状态与远端清单；
2. 拉取远端变更并写入本地；
3. 推送本地变更到远端；
4. 处理冲突；
5. 更新状态文件。

### 5.3 冲突处理

- 按 `updated_at` 比较，较新者胜出；
- 被覆盖的一方另存为 `*.conflict` 文件；
- 冲突记录写入本地冲突列表。

### 5.4 状态文件

- `.sync/state.json` 记录 `last_sync`、`pending`、`conflicts`。
- 所有步骤完成后原子写入。

### 5.5 失败与重试

- 网络失败时不阻塞本地读写；
- 失败的变更进入 pending，下次启动或手动 `notes sync` 时重试。

### 5.6 配置

- 用户配置远端地址与认证方式；
- 配置文件放在 `~/.notes/config.toml`。

## 6. 里程碑

- **M1 数据模型与迁移**：id/updated_at/sync_state 落地，旧数据迁移。
- **M2 同步协议**：远端清单、拉取、推送。
- **M3 冲突处理**：冲突检测、另存、列表与选择。
- **M4 恢复与收尾**：重试、状态恢复、文档。

每个里程碑完成后跑一次双机模拟验收。

## 7. 测试

- 单元测试覆盖数据模型与冲突比较；
- 双机模拟：两台机器、交错编辑、断网恢复；
- 手工验收：冲突场景与状态文件可读性。

## 8. 风险

- 同步过程中断导致数据丢失；
- 冲突判定错误导致静默覆盖；
- 并发进程写坏状态文件；
- 远端不可用时的用户体验。

## 9. 待定
