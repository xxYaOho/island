# 判级锚：yes-designer 工作流（v4 审查时点）

> 本文件由计划作者（Orchestrator）提供，用户已确认。它只包含判级所需信息，不含设计理由、既成取舍或替代方案。

## 第一用途

`yes-designer` 管理并推进设计落地：把任意来源的设计输入转换为统一的 Design Reading，建立并维护持久的实现基线，把设计工作拆成可独立验收的切片，并组织从基线、实现、分层验收到快照沉淀的闭环。使用者是设计师与 lead agent。

## 成功标准

1. **重放事故 B 被拦下**：页面被从零重写时验收必须失败；按基线复制再修改时验收必须通过。
2. **跨会话可接续**：一个全新会话只读工件，就能判断下一步做什么，不需要 agent 记忆。
3. **结构决策不可自批**：agent 不能自行批准 `new`、`independent`、修改共享组件或更新 golden。
4. **退化可被发现**：已经批准的区域在后续轮次被改坏时，必须能被机械发现。

## 非目标

- 代替 Human 做视觉品味、设计代际与产品语义判断；
- 解读 Sketch 原始事实；
- 通用派发、上下文隔离与工程执行；
- 提供项目级测试框架或 CI 集成。

## 不可接受的失败形态

- 从零重写的页面通过验收（事故 B）。
- 新会话无法判断下一步，或只能依赖 agent 记忆维持一致。
- agent 自行批准结构降级、共享组件修改或 golden 更新。
- 已批准区域的退化在后续轮次漏检，且无工件记录。
