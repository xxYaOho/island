# 渐进长厚与修复验证 eval（v0.2 → v0.3.0）

2026-10-26 两轮评估：v0.2.0 渐进长厚纪律首评发现问题，v0.3.0 修复后逐字复跑全部关闭（case1 5/5、case2 13/13、case3 26/26，脚本偏差 3 处 → 0 处）。原始报告见 [《渐进长厚 eval v0.2》](../raw/2026-10-26-eval-v0.2-layered-growth.md)、[《修复验证 eval v0.3》](../raw/2026-10-26-eval-v0.3-fix-verify.md)。

## 失败模式与修复判例

- **升层门控过松**：agent 把任何实质性用户输入都读作「同意往下写」——形状拍板即升草案、评审意见轮同轮升实施，草案确认闸门被吞。修复措辞（0.3.0，已验证有效）：**升层许可必须指向计划动作本身**（要计划 / 升到草案 / 草案通过 / 可以写实施 / 要分派），形状选型、参数拍板、评审意见等纯内容编辑不构成许可；无显式信号时停在当前层并询问。判例：评审意见是对草案内容的反馈，不是对草案的通过。
- **来源不可辨析**：对话拍板、全局约束、我方裁量同语气混写，导致**正确主张也会被审查者误判为失实**（0.1「来源失实」的变体——问题不在造假，在不可审计）。修复（0.3.0 自检条目，已验证有效）：非纯对话来源标注档位（对话 / 全局约束 / 我方裁量 / repo 事实）。实测档位机制还能主动拦错标（评估中发生一次自纠）。
- **bash 3.2 多字节陷阱**：`echo "... $var（..."` 的全角括号在 bash 3.2 + `set -u` 下被并入变量名 → unbound variable、exit 1（核心工作已完成，退出码误导）。修复：插值一律 `${var}`。冒烟脚本因环境 bash 较新未暴露，由生产评估发现——机械冒烟不能替代多环境实测。

## eval 方法论沉淀

- 预注册 rubric + 主脚本逐字跨版本复用 → 两轮严格可比；修复验证的直接证据形态 = **失义信号重获意义**（v1 因提前升层跳过的 T3/T5 信号，v2 按设计走完）。
- 快照链（每阶段留存文档副本）使 state 轨迹与「未到的层不出现」机械可验，不依赖 agent 自报；agent 自报出现过计数误差（9 vs 11 Task），以产物为准。
- 成本旁证：纪律修复后 token 大降（case2 -78%），越层写作本身就是浪费。
- 残留观察：术语承接（加分项口径）两轮均为注入后承接，较 0.1 自发挖掘回退——0.4 候选议题。
