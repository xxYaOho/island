# Executor 施工冒烟：M1 段 A/B 对照

## 核心发现

1. **手册时效税实证**：A 全部 5 次返工源于计划预写代码与本机 SDK 不兼容（`percentEncodedQuery` 可选解包、`NSPanel` 无 `layoutSubtreeIfNeeded` 等——Swift 6.4 / macOS 27 环境演进）；执行者判断失误为零，错误全部自计划侧传入。手册代码计划时是对的，施工时已过时——预写代码的时效风险随环境演进率上升。
2. **承诺自足实证**：B 追问为 0，未出现「计划未覆盖且阻塞施工」——「自足 = 判据完整 + 边界明确 + 上下文指引」在真实施工中成立。12 条自决假设全部是微观设计（TOML 最小解析子集、快捷键须带修饰键、损坏配置回退等），与[执行层详细度定位](execution-layer-detail-level.md)「高档位只出高维度承诺，微观下放执行者」精确吻合。
3. **手册硬编码脆弱性**：A 写死测试计数（计划写 22，范围变化后实际 23）与固定提交信息前缀，执行者被迫做「等价判定」才能推进——精确到数字的承诺，环境一变就变成需要解释的偏差。
4. **切片回读模式**：B 对四个切片（Decision / Draft / Implement / Milestone-1）各 Read 恰好 1 次（开工通读），全程零回查——契约信息一次性装载即够用。支持 split.sh 将 Draft 契约闭包内联进 Milestone 片：单片自带闭包消除「分派带几片」的编排决策，且不增加实际上下文负担。
5. **测试资产归属**：B 自建 58 项测试捕获 1 个真 bug（备份路径 `appendingPathExtension` 产生双点文件名）；A 照抄手册测试（23 项）无此增益。执行者自写测试 = 施工期质量资产——「微观下放」不仅省计划 token，还产出计划时无法预知的验证。

## 效度与后续输入

- 效度：B 派单后停滞 612s 已从活跃时长扣除（JSONL 时间戳实证）；两线零追问与「提问文化」不冲突——施工期问题全部被计划覆盖或按协议自决留痕；真实 API / 人工 UI 验收项两线均跳过（离线等价覆盖），GUI 行为未验证；token 采自 JSONL 逐消息聚合。
