# 假设账本来源失实与三档标注

计划创建 A/B 评估暴露的失败模式：**把「未问」记成「用户未表态 / 未要求」**（[Eval 报告](../raw/2026-09-07-plan-creation-eval.md)）。需求口径真源为冻结的 [Truth Card：学者双语阅读](../raw/2026-09-07-plan-creation-truth-card.md)。

## 踩坑记录

- A3（strict FATAL）：用户拍板过「整篇预翻」，A 未问，却在计划中记为「用户未要求」并把该场景排除——判词「不可能从合规访谈中产生」。
- A 终稿残留：「自研 = 用户已确认」——实际源于主持人一次裁量应答（卡上无口径），进产物后被归为用户立场（W2）。
- B 轻度同款：「无 Node 运行时」作为事实写入结论，实为从未问过环境运行时（node 22 实际存在）。
- v0.2 变体（渐进长厚 eval）：对话拍板、全局约束、我方裁量同语气混写，导致**正确主张被审查者误判为失实**（「用户偏好 TS/pnpm」实有全局约束来源，仍被判分者初判为捏造后经用户纠正撤回）——问题不在造假，在不可审计。

背景改善：上轮共同短板「零自发提问」本轮两线均有改善，且两线都产出显式假设结构（A「撰写人决策（可推翻）」节、B「我方决策（已声明假设）」节）——上轮改进假设（强制确认清单）方向正确，且不专属于 go-spec。坑从「不问」下移到了「问了/没问但记错来源」。

## 解法进展

1. 假设清单三档标注：轻量版已于 **0.3.0 落地**（自检条目「来源档位」：非纯对话来源标注 对话 / 全局约束 / 我方裁量 / repo 事实），并经 [渐进长厚 eval](layered-growth-eval.md) 验证——档位机制还主动拦下一次错标。全量三档（含「未核实：问过吗？答过吗？」与强制引原话）仍为候选，未拍板。
2. 环境事实（运行时、依赖、版本）列入 grill 必问项（对应「无 Node」臆测）——v0.2 eval 中环境主张已全部假设化 + spike 门控，方向有效。
