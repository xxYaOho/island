# 增量复审契约的 fresh-agent 盲区

> 踩坑（2026-09）：多轮审查的「增量契约」（round>1 只发上轮缺陷清单 + 对应修复 + 声明受影响节，禁止重发全文）在修复为局部编辑时以极低成本保持审查质量；一旦修复重构了骨架，它产出「只对 payload 成立、对整体不成立」的 PASS。四轮实证（R1 v0.5.1–R4 v0.5.4，同一任务）同轮验证了文本级场景的收益与结构性返工场景的失效。后续决策将结构性修正改为同一生命周期内复用 reviewer、仅在受控重启时使用 fresh 全量审查。（[增量复审契约的 fresh-agent 盲区](../raw/delta-review-fresh-agent-blindspot.md)；[Strict 飞轮四轮上限与生命周期重启决策](../raw/strict-flywheel-four-round-decision-2026-09-09.md)）

## 命题：契约安全性的隐含前提

增量契约的安全性依赖一个隐含前提——**修复是对原文的局部编辑**。

- 前提成立（缺陷为参数级/声明级，计划骨架不变）：契约以极低成本保持审查质量。
- 前提不成立（修复重构骨架）：契约产出只对发来的片段成立、对整体不成立的 PASS，且无人察觉。

## 三种传输方式下审查者的形态

传输方式不是实现细节，它决定审查者手里有什么。

| 传输方式 | 审查者手里有什么 | 结构性返工下的表现 |
|---|---|---|
| fresh 派遣 + 全文 | 完整当前计划 | 全量视野成立；代价是逐轮重读全文（round 多时的主成本） |
| 同会话续派（消息注入）+ 增量片段 | 首轮全图（记忆）+ 各轮片段 | **基线分叉**：记忆中的计划与真实计划失去同一性，分叉量随轮次增长且不显式——审查者无法知道自己有多过时 |
| fresh 派遣 + 增量片段 | 只有片段 | 最弱：无基线，「缺陷是否真消除」只能对修复文本做字面核验，跨节一致性问题不可见 |

实测：R3（三轮独立派遣 + 全文重放）审查收敛三轮、主会话 $0.536；R4（单会话续派 + 增量）同类缺陷敏感性不变、两轮收敛、主会话 $0.134（-75%）。文本级修复场景下增量契约的收益是实测的（费用口径见[多代理运行的费用核算与价值基准](multi-agent-run-cost-accounting.md)）。

## 失效机制（三层叠加）

1. **基线分叉**（续会话模式）：审查者持有的「全图」停留在首轮；每轮增量都让真实工件进一步偏离其记忆版本。上下文没有「过期」，是与被审对象悄然失去同一性。
2. **verdict 语义相对化**：PASS 的含义随 payload 收缩自动从「这份工件成立」降级为「发来的片段成立」。契约文本不写这个降级，但它机械发生。
3. **契约主动收窄**：典型条款把「对未重发材料的发现」降级为 ESCALATE 而非 FATAL，并以无条件禁令封死重发全文——后果是审查者即使察觉骨架漂移也无权升级发现，编排者即使意识到结构变更而主动重发全文反而违规。**安全行为在现行文本下不存在。**（[增量复审契约的 fresh-agent 盲区](../raw/delta-review-fresh-agent-blindspot.md)）

## 申报困境：编排者诚实也没用

失效的第一因是申报不足（审查范围由编排者声明），但结构性变更的辐射半径难以自估——写出劣化修订稿的编排者并不认为自己动了骨架。申报不足可以完全出于诚实的能力边界：**不知道自己碰坏了什么的时候，正是最需要独立全量视角的时候。该失效模式的触发概率与事故严重度正相关**，这是它与一般契约漏洞的本质区别。

实证对照：R4 两处首轮 FATAL（schema 参数级错误、回退声明越界）的修复辐射完全落在已声明节内，增量审查成立；R3 的 FATAL（里程碑边界打断命令层）的修复辐射覆盖 节点边界/可动文件清单/下游输入假设/gate 核验语义/验收归属 五类骨架字段，任何一类漏报都使审查者对未发节不可见。

## fresh 的语义分层

「Fresh Agent」原则的本义是独立于作者（不 self-critique），不要求同一生命周期的每轮都更换审查者。结构性修正虽然切换为 `FULL`，仍复用该生命周期的 reviewer；只有生命周期耗尽或早停后经用户授权重启，才使用 fresh reviewer。这样把「独立于作者」「生命周期连续性」与「重启时的新视角」分开处置。

## 修复方向：机械分支，不依赖申报自觉

1. **骨架字段触发器**：增量 payload 必填声明——本轮修复是否变更任一骨架字段（以计划书为例：节点边界 / 执行形态标注 / 可动文件清单 / 验收标准的归属节点 / 交付物构成）。任一为是 → 在同一生命周期内切换 `FULL`，并传入完整修订工件；全否 → 维持 `DELTA`。判据用工件中本就显式的字段，不依赖主观判断「是否结构性」。
2. **生命周期边界**：一轮生命周期最多 1 次初审 + 4 次修正；同一实质 FATAL 两轮未缩小，或两轮持续引入新 FATAL 时提前停止。耗尽或早停后不自动换 reviewer，必须取得用户授权；重启才使用 fresh reviewer、Round 1、`FULL`，并附完整当前工件、FATAL 台账与前轮摘要。
3. 成本核算：常见路径保留 `DELTA` 的节省，只有受控重启才支付 fresh 全量审查成本；原稿不变时禁止换 reviewer 寻求 PASS。

## 适用边界

- 适用于一切「多轮审查 + 裁决语义」的编排设计：计划复审、报告复审、gate 复核、外部评审代理。不限于编码任务。
- 增量契约的适用性判据不是任务规模而是**修复的拓扑类型**；判据本身必须可机械检验（骨架字段清单），不能依赖修复者的自我评估。
- 传输方式（续会话 vs 重新派遣）应与裁决语义一并显式设计。
