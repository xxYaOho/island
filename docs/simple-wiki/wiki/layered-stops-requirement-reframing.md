# 分层停点与需求重构

从计划创建 A/B 评估提炼的三条结构性机制（[Eval 报告](../raw/2026-09-07-plan-creation-eval.md)，n=1 方向性结论），需求口径真源为冻结的 [Truth Card：学者双语阅读](../raw/2026-09-07-plan-creation-truth-card.md)。

## 1. 错误在哪一层被发现，决定返工半径

- A（无停点）：错误需求直接长成 2031 行草案 → strict 全文审出 2 FATAL → 整篇重写 1174s。错误穿透到产物深层，返工以「整篇重写」计。
- B（Draft 停点）：错误在 grill 层被自我修正（未进入产物）；Decision + Draft 一次过闸，评审 7 WARN 作为输入被执行层消化（三级识别链 / 缓存版本键 / 段数守恒断言均有具体承接），零返工轮。
- 跨轮互洽：上轮「兼容缺陷在 Draft.md 被抓住」，本轮「需求误解在 grill 层被消化」——分层把不同性质的错误截留在不同便宜层级。

## 2. 澄清导向决定需求重构是否发生

两线拿到逐字相同的重构素材（用户同一句「大部分时间整篇读，先整个翻成中文通读，存疑段落才想对着原文看」），消化结果截然相反：

- B（定位导向）：grill 把它产品化——「这不是一个划词工具加个整篇翻译，而是一篇论文双语对照阅读器加划词查证」，第 2 轮具体化为方案选项（段落级对照 HTML），贯穿终稿（标题即 bilingual-paper-reader）。
- A（参数化导向）：同一段素材被消费为两个局部参数（A1 快捷键而非自动弹出；A3「整篇预翻沿用用户现有方式，不做进工具」）——已知主场景是通读译文，却拒绝服务该场景。strict R1 判词：「A3 不可能从合规访谈中产生」（用户拍板过整篇预翻，A 未问却记为「用户未要求」）。

结论：writing-plans 以「把需求写成可执行手册」为导向，澄清服务于参数化；go-spec 的决策层/grill 以「需求的 Problem/Solution 结构」为导向，澄清服务于定位。信息相同，消化器官不同——需求重构承载力是 writing-plans 结构上不具备的（第二个实证）。

## 3. 信息获取时机决定设计完整性

用户痛点「反复查同一术语、译法统一」写在 truth card 上：A 从未问到 → 终稿无术语机制 → 分块独立翻译造成跨块术语漂移，「直接损伤通读体验」——盲点不是少个功能，而是核心体验带伤。B 在 grill 第 2 轮正面挖到（问 4：本篇历史 vs 跨篇术语本），设计为跨篇术语本一级功能。

A 在 R1 FAIL 后有开放补问机会（≤3 轮）但放弃了，按 strict 判词直接重构——裁决文书只纠正它指出的问题，用户立场的其余部分依然不可见。补问窗口的价值在 strict 之前，不在之后。

与 [假设账本来源失实与三档标注](assumption-ledger-source-falsification.md) 的区别：本页是「没问到」导致的盲区；来源失实是「问了或没问，却记成了用户立场」的标注失真，属另一失败模式。
