# Truth Card：学者双语阅读

> 冻结于 2026-09-07，杨桃拍板。评估主持者与 strict 审查者的唯一应答依据，跑动期间不可修改。生产者（A/B 子代理）不可见本卡。

## 用户故事（真实）

研究学者，第一语言为中文（非英文），日常需要浏览英文论文。期望以第一语言（中文）为主进行阅读，在必要时查看原文，加深理解。

## 需求真相（双层结构）

- 表面方案（用户嘴上说的）：划词翻译小工具——用户认知范围内的想法
- 真实需求（用户想要的）：双语对照阅读——整篇以中文译文阅读，局部存疑时对照英文原文
- 关系：划词翻译只是真实需求的局部表达（按需查证的入口之一），整篇通读对照才是主场景

## 应答口径（逐决策点）

### 需求重构层

1. **读论文的方式**：整篇通读为主；先读译文，遇到看不懂或疑似翻译失真处才需要看原文
2. **划词的动机**：对照确认（译文可疑时核对原文），不是孤立查词背词
3. **呈现期望**：段落级对照——默认显示译文，按需查看原文。用户自己没意识到这点；被问到「想看到什么样」时答「翻译看不懂的地方，能对着原文看就好了」

### 方案层

4. **载体**：论文怎么进系统——主要读 PDF（arXiv 下载为主），偶尔网页版；粘贴文本/导入 PDF/浏览器均可接受
5. **翻译方式**：整篇预翻——导入后整篇翻译好，再进入阅读（杨桃拍板）；非按需逐段翻
6. **翻译引擎**：免费云 API 起步，架构上留本地引擎替换口子
7. **离线**：非硬性，加分项

### 边界层

8. **v1 不做**：PDF 重排版、复习类功能
9. **术语沉淀（加分观察项）**：反复查的术语应记住、全文统一译法——被挖掘到或设计到记为加分，未挖掘不扣分

### 环境事实

10. macOS 15，node 22 可用；不要 Electron 级重量，偏好轻量脚本或原生

## 统一应答规则

- 未问不答
- 问到的按上述口径以用户第一人称口吻作答
- 计划外问题（卡上无口径）统一答：「这个我没特别想过，你按你的建议来，但要说清楚你假设了什么」
- grill / 补问轮次上限：3 轮
- 主持人不得主动补充卡上信息，不得暗示卡上口径
