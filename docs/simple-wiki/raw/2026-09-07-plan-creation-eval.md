# Eval 报告：go-spec 0.4 vs writing-plans——计划创建能力对比（2026-09-07）

> n=1、同模型（glm-5.3-flash）生产与 strict 审查、同一主持人按冻结 truth card 以用户第一人称应答、strict 合同预注册（需求忠实度 + 可施工性，持 truth card 模拟用户验收）。方向性结论。
> 场景：表面方案「划词翻译小工具」包裹真实需求「双语对照阅读」（整篇预翻、L1 通读为主、存疑对照原文）；truth card 含 10 决策点 + 边界 + 1 加分项（术语沉淀）。
> 产物：`route-a/plan.md`（A 终稿）、`route-b/docs/island/plans/2026-09-07-bilingual-paper-reader.md` + 7 切片（B 终稿）。全程未施工代码（按设定，终点 = 实施计划完成）。

## 结果总览

| 维度 | A：writing-plans | B：go-spec 0.4 |
|---|---|---|
| strict 结果 | R1 **FAIL**（2 FATAL）→ R2 **PASS**（4 WARN + 4 MINOR） | R1 **PASS**（0 FATAL，7 WARN） |
| 需求重构 | **未发生**；strict 逼出后部分回归 | grill 第 2 轮**自发完成**，贯穿终稿 |
| 澄清结构 | 1 回合 5 问（参数层） | grill 2 轮 10 问（需求层 + 参数层） |
| 决策点覆盖 | 约 3.5/10（范围、平台、引擎） | 约 8.5/10（含加分项术语沉淀） |
| 生产时长 | 约 39.6 分钟（三版：v1 作废大半 + v2 重写 + v3 终稿） | 约 16.5 分钟（一稿过闸 + 执行层 + 切片） |
| 全链时长（含 strict） | 约 50.7 分钟（strict 2 轮） | 约 21.6 分钟（strict 1 轮） |

| 术语加分项 | 未挖到；代价显影为设计盲点（跨块术语漂移） | 挖到并设计为一级功能（跨篇术语本） |

## 核心发现

### 1. 需求重构力：本轮最干净的对照

两线拿到了**逐字相同**的重构素材——用户在应答「触发/理想操作」时给出了同一段真实用法描述（「大部分时间整篇读，先整个翻成中文通读，存疑段落才想对着原文看一眼」）。

- **B**（grill 第 1→2 轮）：主动把它产品化——「这不是一个划词工具加个整篇翻译，而是一篇论文双语对照阅读器加划词查证」，并在第 2 轮把重构具体化为方案选项（段落级对照 HTML），最终贯穿终稿（标题即 bilingual-paper-reader）。
- **A**（1 回合澄清）：把同一段素材消费为两个局部参数——A1（快捷键而非自动弹出，因「通读为主、查询低频」）与 A3（「整篇论文翻中文通读沿用用户现有方式，不做进工具」）——即**已知主场景是通读译文，却拒绝服务该场景**，把重构机会标注掉了。

strict R1 对 A 的判词切中要害：「A3 不可能从合规访谈中产生」（用户拍板过整篇预翻，A 未问却记为「用户未要求」）。

**解释**：writing-plans 的方法论以「把需求写成可执行手册」为导向，澄清服务于参数化；go-spec 的决策层/grill 以「需求的 Problem/Solution 结构」为导向，澄清服务于定位。信息相同，消化器官不同。

### 2. 工作流结构：错误在哪一层被发现，决定返工半径

- **A（无停点）**：错误需求 → 直接长成 2031 行草案 → strict 全文审出 2 FATAL → 重写 1174 秒（v2）→ 再审 → 终稿。错误穿透到产物深层，返工以「整篇重写」计。
- **B（Draft 停点）**：错误在 grill 层就被自我修正（未进入产物）；Decision + Draft 停点一次过闸，评审意见（7 WARN）作为输入被执行层消化（三级识别链 / 缓存版本键 / 段数守恒断言均有具体承接），无返工轮。

与上轮 eval 的结论互洽：上轮「兼容缺陷在 Draft.md 被抓住」，本轮「需求误解在 grill 层被消化」——分层把不同性质的错误截留在不同便宜层级。

### 3. 假设账本：标注行为普遍出现，新的失败模式是「来源失实」

上轮共同短板「零自发提问」在本轮两线都有改善（A 的方法与 B 的 grill 都触发了提问），且**两线都产出了显式假设结构**（A「撰写人决策（可推翻）」节、B「我方决策（已声明假设）」节）——上轮的改进假设（强制确认清单）方向正确，且不专属于 go-spec。

但本轮暴露了更深一层的失败模式：**把「未问」记成「用户未表态/未要求」**。A 的 A3 是典型（strict 判 FATAL-2）；A 终稿仍残留「自研 = 用户已确认」的归类失实（W2，源于主持人一次裁量应答，见过程事件 1）；B 也有轻度同款——「无 Node 运行时」作为事实写入结论，实为从未问过环境运行时（node 22 实际存在）。

**指向**：假设清单需三档标注——「用户原话」「我方决策（已声明）」之外，还需「未核实（问过吗？答过吗？）」；或至少强制「凡归入用户立场的事实必须引用访谈原话」。这对 go-spec 0.5 的决策层模板是具体可落地的改法。

### 4. 信息获取时机决定设计完整性：术语盲点

用户痛点「反复查同一术语、译法统一」写在 truth card，A 从未问到 → 终稿无术语机制 → strict MINOR 指出其分块独立翻译将造成跨块术语漂移，「直接损伤通读体验」——盲点不是少个功能，而是核心体验带伤。B 在 grill 第 2 轮正面挖到（问 4：本篇历史 vs 跨篇术语本），设计为跨篇术语本一级功能。

A 在 R1 FAIL 后被开放补问（≤3 轮），**放弃了**——判词建议「先问清用户真实阅读工作流再改」，A 选择按判词直接重构。代价即刻显影：裁决文书只纠正它指出的问题，用户立场的其余部分 A 依然不可见。

## strict 表现

- 判罚一致性：同一合同 + 同一 truth card。两轮对 A 的裁决精确递进（R1 抓方向、R2 验证修复真实性并抓残留）；对 B 的 7 WARN 质量高（伪造用户立场、三处契约空洞均有施工级依据）。
- 一处可辩裁量（如实记录）：A R2 对「左英右中并排 vs 口径 3 按需展开」以体验判准降为 WARN（中文列主导阅读、不满意可能性低）而非 FATAL。B 无对应物（精确按口径设计）。口径字面与体验判准的取舍，属合同解释空间，非判罚不一致。
- strict 各轮均主动核查访谈合规性并标注 UNVERIFIED（主持人应答过程不在其视野）——审查者知道自己看不见什么，判词质量可信。

## 过程事件（影响效度，如实记录）

1. **主持人裁量 1 处**：A 问「自研 vs 现成方案」，truth card 无口径；为防路线跑偏以「想自己弄一个」应答并当场向用户报备。该应答进入 A 的产物并被记为「用户已确认」，持卡 strict 判归类失实（W2）。缝隙：裁量应答进产物但 truth card 不可见。修正：此后裁量应同步追加至卡的附注（或过程日志），保持 strict 视野完整。
2. **子代理通知的 token 字段失效**（全部显示 0，与上轮相同）：改从子代理 JSONL 转录逐消息聚合恢复（见附录 token 明细），数据完整。
3. **两线均未卡死**：上轮 2 小时卡死 ×2 未复现；通知信道本轮可靠。
4. strict R2 未提供 R1 WARN 原文逐条核对（UNVERIFIED 自报），仅确认对应机制存在——跨轮核验链有小缺口。

## 结论（方向性）

在「自然语言需求 → 草案 → strict 闸口 → 实施计划」管线上，同模型同主持人条件下：

- **A（writing-plans）**用 2.3 倍时长、4.8 倍篇幅、手册级代码预支交付了一份工程扎实的产品计划——但产品方向第一枪打错，靠 strict 逼回；终稿呈现形态与用户口径仍有可辩偏差，用户立场的部分内容（术语统一）始终不可见。
- **B（go-spec 0.4）**在信息层（grill）完成需求重构，一次过闸；分层结构使评审意见被下一层消化而非触发重写；切片与里程碑（按风险切分 + 并行论证）为后续分派就绪。代价是执行者需要判断力（承诺立场，本轮未施工验证）。

**go-spec 设计合理性**：本轮获得第二个实证支持——决策层/grill 对「需求重构」的承载力，是 writing-plans 方法论结构上不具备的（同素材、同模型，A 未消化）。停点设计有效截留了不同性质的错误。

**改进指向（0.5 候选）**：
1. 决策层「我方决策」与「用户结论」强制分栏，且用户结论必须引用访谈原话（对应本轮「来源失实」失败模式，A/B 均犯）。
2. 环境事实（运行时、依赖、版本）列入 grill 必问项（对应 B「无 Node」臆测）。
3. 上轮遗留：executor 施工冒烟仍未验证（承诺立场的最终试金石），建议作为下一轮 eval 主轴。
