# 多代理运行的完整费用核算与价值基准 (DeepSeek 峰价)

> 方法与实证记录 (2026-09-04)。来源: yes-subagents coding workflow 的 E3 微评估三轮 (v0.5.1/v0.5.2/v0.5.3), 同一任务 (micro-note JSON→SQLite 迁移), stream-json 无头会话。实测执行于 glm-5.3-flash, 以 DeepSeek v4-flash 官方峰价折算作为跨服务商可比的计价口径。

## 一. 计费模型: 轮次 x 上下文重放

Agent 会话中, 每一个 turn 模型都要重新处理此前全部对话前缀 (工具结果/文件读取/派遣指令) 才能生成该轮增量。Prompt cache 使重放远便宜于新输入 (实测口径: 命中 $0.014/M vs 未命中 $0.44/M, 约 31 倍价差), 但仍按 turn 逐次计费:

```
cache 读账单 ≈ Σ(每个 turn 的上下文体量) ≈ turns x 平均上下文
```

自检实例: 81 turns x ~53.5k 平均上下文 ≈ 4.33M, 与实测 cache_read 4.34M 吻合。

推论:

1. 降本杠杆只有两个——减少 turn 数, 压薄常驻上下文。生成量 (输出 token) 是零头 (三轮中占 3%-10%)。
2. 轮询的经济学定性: 每次轮询 = 一次全量上下文重放, 换回零信息 (完成通知免费推送)。与 [[orchestrator-polling-context-bloat]] 的机制同源, 该页提供行为教训, 本页提供定价公式。

## 二. 核算口径 (硬性): 主会话 + 全部嵌套子代理会话

**stream-json result 行的 usage 只含主会话**。子代理是独立计费会话, 只按主会话记账会严重低估——E3 实测子代理占总账 23%/42%/35% (详见第四节), 漏算最多近半。

完整口径:

1. 主会话: transcript 的 result 行 usage (timing 脚本既有口径, 须全段累计)。
2. 一级子代理: `~/.claude/projects/<主会话cwd-slug>/<session_id>/subagents/agent-*.jsonl`, 按每条 assistant 消息的 usage 逐条累加 (cache 读按次计费, 与计费模型一致)。
3. **二级嵌套探测必做**: 取各子代理自身的 session_id, 再查其 `<slug>/<session_id>/subagents/` (孙代理)。本实证三轮均为 0 个, 但检查本身是方法的组成部分, 不可省略。
4. 失败派遣 (如 `Agent type not found`) 不产生会话, 不计费, 但须对账说明 (派遣次数 - 失败次数 = 会话数)。

## 三. 价格基准: DeepSeek v4-flash 峰价

2026-08-16 DeepSeek 调价后 (多源核实: 官方定价页, TechJack, packet.ai 等), v4-flash 按峰谷计费:

| 项 | 峰价 ($/M tokens) | 谷价 |
|---|---|---|
| 输入 (cache miss) | 0.44 | 0.22 |
| 输入 (cache hit) | 0.014 | 0.007 |
| 输出 | 1.32 | 0.66 |

峰时段: 01:00-04:00 与 06:00-10:00 UTC, 其余为谷时 (约半价)。

**基准提案**: 以 v4-flash 峰价为 yes-subagents 技能运行的价值参考锚——flash 级定价压低了"流程税"的下限, 便于跨服务商、跨执行器档位换算比较 (换 opus 级执行器约 10-30 倍价差)。

## 四. E3 三轮实证

三轮同一任务, token 分项与折算 (峰价):

| 轮 | turns | 墙钟 | 主会话账 | 子代理账 (会话数) | 合计 | 谷时约 |
|---|---|---|---|---|---|---|
| R1 v0.5.1 | 74 | 34m49s | $0.213 | $0.064 (2) | **$0.277** | $0.14 |
| R2 v0.5.2 | 41 | 46m43s | $0.268 | $0.192 (5) | **$0.460** | $0.23 |
| R3 v0.5.3 | 81 | 75m19s | $0.536 | $0.288 (7) | **$0.824** | $0.41 |

交付物质量百分制 (统一尺度的单评估者打分, 维度权重: 功能完成度 35 / 健壮性边界 25 / 测试可验证性 20 / 工程结构与文档 10 / 决策透明度 10):

| 轮 | 质量分 | 每分价格 (峰价) |
|---|---|---|
| R1 | 70 | $0.0040 |
| R2 | 78 | $0.0059 |
| R3 | 95 | $0.0087 |

## 五. 解读

1. **每分价格递增不是流程税**: R1 便宜部分源于跳过了派遣与独立 gate (亲自实施, 子代理占比仅 23%)。质量分 70→95 的最后 25 分买的是健壮性/边界/诚实披露——都是有息负债的免除 (DB 入库的二进制 churn、幂等缺失、失败路径裸奔), 属 TCO 利息前置。一次性脚本场景 R1 反而理性; 技能目前无从得知任务寿命。
2. **子代理的钱是设计成本而非浪费**: "把脏活推进子代理"省的是编排者上下文健康, 钱由子代理自付, 总账不降反升 (R2 子代理占 42%)。买的是独立视角与上下文隔离, 不是省钱。
3. **数据边界**: n=1; 百分制为单评估者尺度; 峰谷价格摆动约 50%; 结论用于量级判断, 不用于精确预算。
