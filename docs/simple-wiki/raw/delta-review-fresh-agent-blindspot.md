# 增量复审契约的 fresh-agent 盲区

> 来源：yes-subagents coding workflow E3 微评估四轮实证（R1 v0.5.1 / R2 v0.5.2 / R3 v0.5.3 / R4 v0.5.4，同一任务 micro-note JSON→SQLite 迁移，无头会话取证）。R4 首次启用复审增量契约并验证其有效性，同轮取证暴露该契约在结构性返工场景的失效机制。实证细节见 workspace iteration-6/REPORT.md §6–§7；费用口径见 [[multi-agent-run-cost-accounting]]。

## 一. 命题

多轮审查的「增量契约」——round>1 只向审查者发送 上一轮缺陷清单 + 对应修复 + 声明受影响的节，禁止重发全文——其安全性依赖一个隐含前提：**修复是对原文的局部编辑**。前提成立时（缺陷为参数级/声明级，计划骨架不变），契约以极低成本保持审查质量；前提不成立时（修复重构了骨架），契约产出「只对 payload 成立、对整体不成立」的 PASS。

## 二. 三种传输方式下审查者的形态

| 传输方式 | 审查者手里有什么 | 结构性返工下的表现 |
|---|---|---|
| 每轮 fresh 派遣 + 全文 | 完整当前计划 | 全量视野成立；代价是逐轮重读全文（round 数多时为主成本） |
| 同会话续派（消息注入）+ 增量片段 | 首轮全图（记忆）+ 各轮片段 | **基线分叉**：记忆中的计划与真实计划失去同一性，分叉量随轮次增长且不显式——审查者无法知道自己有多过时 |
| fresh 派遣 + 增量片段 | 只有片段 | 最弱：无基线，「缺陷是否真消除」只能对发来的修复文本做字面核验，任何跨节一致性问题不可见 |

实证：R3（v0.5.3，三轮独立派遣+全文重放）计划审查收敛耗时三轮、主会话费用 $0.536；R4（v0.5.4，单会话续派+增量）同类缺陷敏感性不变、两轮收敛、主会话费用 $0.134（-75%）。文本级修复场景下增量契约的收益是实测的。

## 三. 失效机制（三层叠加）

1. **基线分叉**（续会话模式）：审查者持有的「全图」停留在首轮；每轮增量都让真实工件进一步偏离其记忆版本。上下文没有「过期」，是与被审对象悄然失去同一性。
2. **verdict 语义相对化**：PASS 的含义随 payload 收缩自动从「这份工件成立」降级为「发来的片段成立」。契约文本不写这个降级，但它机械发生。
3. **契约主动收窄**：典型条款把「对未重发材料的发现」降级为 ESCALATE 而非 FATAL（surplus input does not widen your verdict），并以无条件禁令封死重发全文——后果是**审查者即使察觉骨架漂移也无权升级发现，编排者即使意识到结构变更而主动重发全文反而违规**。安全行为在现行文本下不存在。

## 四. 申报困境：编排者诚实也没用

增量契约的审查范围由编排者声明，因此失效的第一因是**申报不足**。但结构性变更的定义恰恰是辐射半径难以自估——写出劣化修订稿的编排者并不认为自己动了骨架。申报不足可以完全出于诚实的能力边界：不知道自己碰坏了什么的时候，正是最需要独立全量视角的时候。**该失效模式的触发概率与事故严重度正相关**，这是它与一般契约漏洞的本质区别。

实证对照：R4 的两处首轮 FATAL（schema 参数级错误、回退声明越界）的修复辐射完全落在已声明节内，增量审查成立；R3 的 FATAL（里程碑边界打断命令层）的修复辐射为 节点边界/可动文件清单/下游输入假设/gate 核验语义/验收归属 五类骨架字段，其中任何一类漏报都使审查者对未发节（下游节点对上游交付的假设）不可见。

## 五. 审查者形态的另一个变量：fresh 的语义分层

「Fresh Agent」原则的本义是独立于作者（不 self-critique），不约束「同一审查者跨轮次复用」。同会话续派不违反该原则，但引入两个原则管不到的风险：基线分叉（前述）与**锚定偏差**（已 PASS 过一轮的审查者推翻自己前轮裁决的倾向；n=1 无观测样本，方向上与分叉同源）。设计多轮审查时，「独立于作者」与「每轮独立视野」是两个必须分开处置的维度。

## 六. 修复方向：机械分支，不依赖申报自觉

1. **骨架字段触发器**：增量 payload 必填声明——本轮修复是否变更任一骨架字段（以计划书为例：节点边界 / 执行形态标注 / 可动文件清单 / 验收标准的归属节点 / 交付物构成）。任一为是 → 回落 fresh 派遣 + 全量重审；全否 → 维持增量。触发判据用工件中本就显式的字段，不依赖主观判断「是否结构性」。
2. **禁令条件化**：「never resend the full artifact」改为——非结构性修复禁止重发全文；结构性变更**必须**重发全文并 fresh 派遣。
3. 成本核算：只有罕见轮付全价。四轮实证中 3/4 的审查轮次为文本级修复（R1 两轮、R2 两轮、R4 两轮中仅 R3 的 v2→v3 一轮为结构性），常见路径的节省全部保留。

## 七. 适用边界

- 适用于一切「多轮审查 + 裁决语义」的编排设计：计划复审、报告复审、gate 复核、外部评审代理。不限于编码任务。
- 增量契约的适用性判据不是任务规模而是**修复的拓扑类型**；判据本身必须可机械检验（骨架字段清单），不能依赖修复者的自我评估。
- 传输方式（续会话 vs 重新派遣）不是实现细节，它决定审查者形态；应与裁决语义一并显式设计。
